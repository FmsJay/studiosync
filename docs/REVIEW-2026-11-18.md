# Review of 2026-11-18 (0.59.13 → 0.59.15): what was found, fixed, and left

Twelve reviews ran over the whole codebase and the recent changes: UI layout (floating, docked across the bottom, docked beside
another dock, docked at a side), UX and wording, the 0.59.8–0.59.13 changes, sync edge cases, efficiency, code cleanup, live
plug-in tests in REAPER, Mac and cross-platform readiness, and full reads of the sync engine, the panel and its pages, live audio
with services and security, and media, files and restore. Their verified findings were fixed in 0.59.14 (with three fixer branches
merged: sync engine, security and services, efficiency; and a cleanup branch) and 0.59.15. The code comments marked "0.59.14"
say what each fix was for.

## Fixed, in short
- New: the call in a window of its own (lib/callwin.lua): mute and unmute, hold to talk, mic and level, your volume and
  everyone's, deafen, who's in the call, the studio's video call. Chat > Call > Pop out, or the box's right-click menu.
- Docked: page tabs drop to a row of their own when a part-width bottom docker can't hold them; columns that don't fit stack in
  the last one instead of scrolling sideways; pills and live icons wrap; Restore, Advanced and Colours rows fit narrow columns;
  Home's live ideas sit in a column; the toast is one line; Chat's tabs scroll; the bars take three rows.
- Sync engine: a restore or undo back to before a track's first plug-in or automation removes it everywhere; a stuck "not sent"
  flag on a deleted track's parts no longer beats a bandmate's restore; Local mixing and Follow no longer send your faders; a knob
  or preset inside an FX container is sent; a trim and a move no longer merge into a state neither made; pooled MIDI is unpooled
  before a change lands; a re-imported file at the same path isn't swapped for its stale copy; take-FX sample files travel; claims
  follow their owner's rename; restores past trimmed history don't delete; a malformed newest event no longer hides valid ones.
- Panel: Restore, Bring into and Time-sync no longer act on another tab's project after a tab switch; the box and banner refresh
  while shrunk; page errors are caught per tab; a frame error is said once; confirms before phone alerts off and Tailscale-only.
- Prints: failures show in the alert bar with Try again; prints rendered here go in only once whole; a failed background print
  renders in front instead of restarting a hidden REAPER every few seconds; long front renders wait for a quiet moment without
  holding up other prints; Windows' Wait-Process limit; one render pass only through REAPER's own plug-ins; job folders start
  empty; an audio print that comes out silent is flagged.
- Security: code changed in a shared-folder install is checked against what you approved before it runs; an admin's save can't
  launder settings a member slipped into band.json; a token that won't decrypt no longer starts PowerShell every 2 s; invitation
  names are cleaned; auto-admit needs the studio's own Tailscale network.
- Mac: the installer's paste flush works on bash 3.2; Cmd+Z bound automatically; the watchdog's sleep doesn't linger; shell
  commands go through script files; the Keychain save is checked by reading it back.
- Efficiency: saved versions read once; one events listing per pass; status writes only when they matter; History warms only on
  its pages; startup work once per REAPER session.
- Cleanup: about 750 lines of the old take-sync receive side and other dead code removed; one ISO-time parser; shared helpers.
- Wording: one name per thing (Video call vs the call, Time-sync, Dry/Wet/Auto, "not sent"), routine counts kept out of the toast,
  errors in plain words, print problems say what to do.

## Tests on the Mac and the laptop (0.59.16 → 0.59.17)
- Mac (REAPER 7.86 arm64): 9 of 10 REAPER suites passed unchanged (take_comps counted pieces, and REAPER on a Mac merges each take's
  pieces into one item per lane: the test now checks each take is still there). VST, VST3, AU and AUi chains go out once, stay put
  while idle, and send and land knob and preset changes; a container child's knob and preset travel; a background print through an
  AU instrument rendered in 11 s, not silent. CLAP knobs set from a script didn't change while the Mac's audio device was closed
  (REAPER's side; re-test with audio running). Its menu extension was 1.0.5 (only the scripts reach it outside ReaPack): 1.0.6 was
  put in place, loaded at REAPER's next start.
- Laptop, 23 third-party setups (FabFilter Pro-Q 3, Pro-C 2 with sidechain, Pro-R, Pro-L 2; Vital VST2/VST3/CLAP; Surge XT VST3/CLAP;
  Dexed VST3/CLAP; Serum; a bridged 32-bit SerumFX; DecentSampler, sforzando, TX16Wx, LABS; TONEX, AmpliTube 5, Darkglass Ultra;
  Odin2; two containers): no crash, no StudioSync errors. Fixed from it in 0.59.17: a container was put on the restless list as
  "Container" (then everything inside every container was left out of the hash); a preset loaded in the first minute after a
  project opened never went out; sforzando's CLAP read as missing; a replaced print's file stayed open until REAPER restarted.
  Also found: Nostalgia on the laptop putting a track's icon back over and over (the icon's path is each computer's own: J:\ vs D:\),
  fixed by comparing REAPER's track icons by name.
- Not bugs: FabFilter, Vital and Serum read back differently after landing (the readback absorbs it: no echo); TONEX and AmpliTube
  expose only unassigned macro slots, so a script's turn of one doesn't travel; stepped knobs land as the value the plug-in snaps to.
- Skipped (activation or login windows): Omnisphere, Superior Drummer 3, Pianoteq, iZotope RX, SWAM, sonible, Ample Guitar, IK MODO
  DRUM and others; RS5K (the morning's crash).

## Left, with why (for later)
- Plug-in edits made during playback are put back if permissions change before you stop: since 0.59.18 the refused chain is saved
  first as an FX chain file (StudioSync's folder, kept plug-ins), named in the "Not sent" line. Automation edits aren't kept that way.
- (Done in 0.59.18: the same song open in two REAPERs on one computer syncs only in the first; the second says why.)
- (Done in 0.59.18: a big file shared into the studio is copied in the background, its item sent once it's there.)
- (Done in 0.59.18: Change name refuses a name StudioSync can't tell from another computer's, as "Al-B" and "Al_B".)
- Docked short: the window buttons can wrap to a second bar row (about 33 px) instead of folding into one menu.
- UX not done: moving the Tailscale token/tags to Settings > Studio for admins; keyboard focus rings and releasing a claim from the
  keyboard. (Done in 0.59.32: a text size setting, Settings > Look, 80-160%.) (Done in 0.59.18: the edit modes "Anyone (claims hold)" / "Anyone (claims ignored)", and Can't
  hear? under Health. Talk stays off Home: James, 0.59.6.)
- Efficiency not done: pruning deleted objects' records from the project; a cached live.fx; the Drive pass's listings; the memo-key
  copies. (Done in 0.59.19, measured at 60 tracks and 2,040 MIDI items: a look 720 -> 215 ms idle, 670 -> 250 ms after an edit. Reading
  the chunks was never the cost (60 ms for all of them): it was StudioSync's work on them. item_hash is memoized, the print checks keep
  each track's routing and plug-ins for the look, the media folder is made once per 10 s, short hashes are kept. History keeps events
  without their state, read back when going back; mirror.memo counts what it holds, 128 MB.)
- Security residue of the code guard: band.lua, json.lua and the entry scripts run before the check; FNV-64 isn't cryptographic;
  binaries and helper scripts in the shared folder (ninjamsrv, lib/listen, lib/mac) aren't covered. Not doing (James, 0.59.19): a
  studio sharing a folder trusts its members; ReaPack installs stay the safe way.
- Three people editing one item at once can settle on different merges on different computers (rare).
- Splitting the biggest functions (mirror.watch, the panel's settings block and frame_app, Live sync's poll) along the seams the
  cleanup review named; ExtState JSON read/write helpers.
- Smooth scroll: Settings bodies don't ease (docked columns do since 0.59.18); a trackpad's momentum tail can stop a few pixels short.
- (Done in 0.59.18: a song name differing only by case from an existing one is that song. Done in 0.59.19: band.clean and the
  installers make the same names from accented letters, letter by letter: macOS's iconv mangled whole names.)
- The desktop REAPER crash during the plug-in test (RS5K with a sample, a background print running) didn't reproduce on the
  laptop in 30 rounds; a 5 s gap between two of the band's chains replacing one track's stays as a precaution.
- (Done in 0.59.19: a background print with nothing selected ends in seconds and renders in front; it waited 3 minutes and blamed a
  plug-in.)
- CLAP knobs changed while REAPER's audio device is closed (seen on the Mac) may only be seen when REAPER applies them.
- (Done in 0.59.27: the menu extension updates from the copy StudioSync runs from, on Windows, macOS and Linux, not only through ReaPack.)

## 0.59.32 (James's list, 2026-11-18)
- Health's "Try again" now reaches Autostart, which receives: it ran in the panel and Autostart's own cache still had the changes as done,
  so nothing was retried until REAPER restarted. The laptop's skipped deletions (Nostalgia, Cross Test, 11-16/17, "can't read it") read
  fine today; why they failed then wasn't found. Try again brings them in.
- Ctrl+Z: Health checked only the copy StudioSync runs from; the keys were on the copy each computer ran from before (which hands over),
  so it called them unset on the laptop and the Mac. Any copy's key counts now. The keys themselves were never changed.
- The pre-rename live mix (Effects/BandSync) is named "StudioSync live mix (older copy)" in REAPER's list, kept for songs that still have
  it until their live audio is set up again.
- A studio that updates through its folder takes a new version without asking (Chilio asked at every release).
- The Tailscale token and tags are under Settings > Studio for the owner and admins (Advanced for anyone else).
## 0.59.37 (the rest of the list)
- Docked short: the bar uses "Exit" wherever "Sync and exit" doesn't fit, so Window and Dock stay on the bar's row (folding them into "..." is
  out: James, 0.58.23).
- Keyboard navigation: Settings > Look, opt-in (Tab and arrows between buttons with a ring, Space presses, so a claim chip's release works
  from the keyboard). Off by default: on, the panel keeps those keys from REAPER while it has focus.
- Text size scales the boxes, cards and page list too, not only the words.
- Settings bodies ease like the pages; a trackpad's momentum tail (moves under half a pixel) is counted, so it doesn't stop short.
- Three people editing one item apart: merged from the versions themselves in one order (mirror.merge_order), the same on every computer
  whatever order they arrived in. Two come out as before.
- Speed: live.fx remembers where SonoBus/ReaNINJAM was found; the Drive pass keeps each Drive folder's listing 30 s (and looks for Drive's
  "(1)" copies only with a fresh listing).
- The panel's box opens for a request from outside (a script, an action), as the radial menu already did.
- Health's audio row says why a CLAP knob turned while REAPER's audio is off reaches the others late.
- Not done, on purpose:
  - Pruning deleted objects' records from the project: trim keeps every object's newest change for good, a deletion included, and restore
    points keep it too; those records are what stop a late older change bringing a deleted thing back and let Restore remove it. A few hundred
    KB of project text isn't worth that.
  - The memo's keys copying whole chunks: each look reads fresh chunks from REAPER anyway, so a hash key would read every byte as well; the
    gain is inside measurement noise.
  - Splitting mirror.watch, frame_app and Live sync's poll, and ExtState JSON helpers: no change anyone sees, and churn in the code everything
    runs through. Done when one of them is next changed for a reason.
