Headphones, latency and pro audio (ASIO)

Use headphones: the session plays here and your input goes back to it, so speakers would send everyone's sound back to them. Monitor yourself on your interface (its direct monitoring), not through this page.

You hear the session about a network trip plus ~0.1 s late, and the band hears you a network trip plus ~0.06 s late: fine to talk and play along; takes still land in time, because they're placed by where the song was when you heard it.

Browsers can't use ASIO drivers. What this page gets per system:

  • Windows: the interface through Windows audio (WASAPI shared mode, the browser's own buffer, often 10-20 ms each way). Set the interface's Windows sample rate to the session's, and close programs holding the interface in exclusive (ASIO) mode, or the browser may see no input.
  • Mac: Core Audio, the interface as it is (low latency; an aggregate device works for more inputs).
  • Linux: PipeWire (or PulseAudio) as the browser's audio; JACK apps through pipewire-jack.
  • Two inputs at most reach a browser page; Chrome and Edge give the lowest latency.
